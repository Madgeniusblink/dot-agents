# Brief for one non-technical person

They will follow this literally, alone, with no context and no ability to
improvise. Every word they need is on the page. Nothing else is.

State the total expected time at the top. Use numbered tasks with checkbox
sub-steps in roughly two-minute chunks.

## Per step

- **One action per step.** "Open Settings and tap Wi-Fi" is two steps.
- **Exact names in bold, verbatim.** Never "the printer network" when you know
  the name.
- **What they should see after the action.** If the outcome varies, give the
  range: "either X or Y appears, both are fine."
- **A failure branch.** "If X is not in the list, stop and send a photo of the
  screen." Stop-and-report always beats guessing.
- **Locations for physical things.** Which room, which shelf, which port,
  which cable color.

## Never

- No secrets. Point at the password manager item by name, never the value.
- No vague words: should, probably, might, simply, just, obviously, as needed,
  if necessary.
- No unexplained jargon. If a technical term is unavoidable, define it in six
  words in parentheses.
- Never guess a menu label. Verify it, or write "the menu name may differ,
  look for a word like X".

## End with two sections

- **You are done when** — observable facts. "The printer screen shows its
  network name", not "everything works".
- **When finished** — exactly how to report back, so completion can be
  verified live.

Verify live after they report done. Never trust the tick. Report drift as "not
yet effective" with evidence, then give one remedy.
