# Contributing

Thanks for improving the shared template.

## Before you open a PR

1. Read [docs/repo-rules.md](docs/repo-rules.md) and the [admission test](standards/extending.md#admission-test-before-you-add-a-file).
2. Run the same checks as CI locally if you can: neutrality greps, link check, budget check, the checks in [.github/workflows/check.yml](.github/workflows/check.yml).
3. Do not name vendors in shipped files. Say "your tool."
4. Record **template** design choices in [docs/decisions/](docs/decisions/), not in `decisions/` (yours).

## Merging

`main` requires the four CI checks and a branch that is up to date. Squash merge. When `main` moves under your PR, update the branch on GitHub rather than rebasing and force-pushing:

```sh
gh api -X PUT repos/Madgeniusblink/dot-agents/pulls/<N>/update-branch
gh pr merge <N> --auto --squash --delete-branch
```

The first adds a merge commit from `main` on the server; the second merges as soon as the checks pass.

## Versioning

Template version and tag URLs live in [context/upstream.json](context/upstream.json) (`template_version`, `release_tag`, `links.raw_tag`). Tag releases on `main` when the template version bumps. A `v*` tag runs [release.yml](.github/workflows/release.yml), generated by [dist](https://github.com/axodotdev/cargo-dist) from [dist-workspace.toml](dist-workspace.toml): it builds `agents` for macOS and Linux, attaches the archives to the GitHub Release, and writes the formula into `Madgeniusblink/homebrew-tap` with the `HOMEBREW_TAP_TOKEN` secret. After a dist upgrade, run `dist init --yes` and commit the regenerated workflow.

## GitHub account settings (maintainer)

Turn on both options under [GitHub → Settings → Emails](https://github.com/settings/emails):

1. **Keep my email addresses private** — web edits and **merge commits** use your `@users.noreply.github.com` address instead of your personal email.
2. **Block command line pushes that expose my email** — rejects `git push` when commit metadata contains a private address.

Also set local Git author email to the same noreply address (see **set your email in Git** on that page). Use **Squash merge** or ensure PR commits already use noreply before merging.

**Already public merge commits** keep their old committer metadata until history is rewritten (requires maintainer approval, retags, and submodule updates). New merges after the settings above use noreply.

Enable **Private vulnerability reporting** on each public repo (**Settings → Security**).

Repository hygiene: **Template repository**, description, topics (`agents`, `template`, `dot-agents`).

## Code of conduct

Be direct and kind. Minimize diff scope.

## Pre-commit review (opt-in)

`scripts/githooks/pre-commit` asks the `claude` CLI, when it is installed, to read the staged markdown for a fact the tree now contradicts and for plain-writing faults ([review-prompt.md](scripts/githooks/review-prompt.md)). A stale fact blocks the commit; a writing fault is printed and lets it through. Turn it on per clone:

```sh
git config core.hooksPath scripts/githooks
```

It is not registered for you, so a clone without it behaves as before, and deleting the clone leaves nothing behind.
